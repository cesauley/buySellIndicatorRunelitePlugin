2. Cleanup candidates (do not auto-delete without review)
---------------------------------------------------------

### 2.1 AnalysisBundle.getPlaystyle()
Location:
  src/main/java/com/buysell/BuySellIndicatorConfig.java
  enum AnalysisBundle → getPlaystyle()

Evidence:
  Production analysis code (PriceAnalysisService) uses getModel(), getApiTimestep(),
  getMaxCandles(), getZScoreSmaPeriod(). getPlaystyle() is only exercised by unit
  tests (BuySellIndicatorConfigTest) and is not read by runtime signal logic.

Risk: Low
Recommendation:
  Keep if you want Playstyle as documented metadata on bundles for future UI
  grouping (e.g. Flipping vs Merchanting sections). Otherwise remove Playstyle
  enum + field + getter if you want a thinner config surface.

Related (NOT unused):
  Playstyle enum values are still assigned in AnalysisBundle constructors and
  stored on each constant; only the getter appears unconsumed by production.


### 2.2 Overlay does not honor config.showOnInventory() / showOnBank()
Location:
  src/main/java/com/buysell/BuySellIndicatorOverlay.java
  Constructor always calls WidgetItemOverlay.showOnInventory() and showOnBank().
  renderItemOverlay() never reads config.showOnInventory() / showOnBank().

Config keys ARE used elsewhere:
  - BuySellIndicatorPlugin.onMenuEntryAdded gates "View Graph" by these toggles
  - BuySellIndicatorSettingsPanel / SettingsDraft expose and persist them
  - BuySellIndicatorConfig defines the @ConfigItem defaults

Evidence of mismatch:
  Overlay comments (~lines 60–66) claim runtime config re-check and/or plugin
  re-registration based on toggles. That wiring does not exist. Toggling
  "Show on Inventory" / "Show on Bank" therefore affects the context-menu graph
  action and settings UI, but overlay labels still draw on both interfaces.

Risk: Medium (behavior / UX gap, not dead code)
Recommendation:
  Either:
    (A) Wire toggles: re-register overlay interfaces on ConfigChanged, or skip
        draw in renderItemOverlay when the parent interface is disabled; or
    (B) Update README + overlay comments to state that those toggles only affect
        View Graph (and rename config items if that is intentional).

This is the highest-value follow-up among the findings.

3. Things that LOOK unused but MUST NOT be removed
--------------------------------------------------
Do not flag these as dead code without understanding RuneLite conventions:

  - @PluginDescriptor / Plugin.startUp / shutDown
  - @Subscribe methods (EventBus reflection)
  - @Provides BuySellIndicatorConfig
  - @Inject fields (Guice)
  - @ConfigItem / @ConfigGroup methods (RuneLite config UI + persistence)
  - NavigationButton + panel_icon.png (loaded via ImageUtil.loadImageResource)
  - BankFilterManager script callbacks (bankSearchFilter, getSearchingTagTab,
    ScriptPostFired BANKMAIN_*) — driven by client script events
  - FilterMode enum on config interface — runtime bank button state, not a
    persisted @ConfigItem, but used by BankFilterManager
  - Signal.FILTERED — used to suppress overlay / lists / menus
  - Lombok-generated getters on SignalResult / event DTOs
